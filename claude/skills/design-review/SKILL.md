# design-review

Сравнивает свёрстанную страницу (или компонент) с фреймом Figma и выдаёт список
расхождений, который можно сразу чинить. Цикл: **сверка → отчёт → правка → повторная
сверка только упавших пунктов**.

Ревью, а не перерисовка: цель — найти, где вёрстка отходит от макета, и показать,
какое место в коде за это отвечает. Код без согласия пользователя не правим.

## Инструменты

| Что               | Чем                                                                 |
| ----------------- | ------------------------------------------------------------------- |
| Макет             | Figma MCP: `get_screenshot`, `get_design_context`, `get_variable_defs` |
| Макет (fallback)  | REST через скилл `biz-agent-kit:figma`, если MCP недоступен         |
| Страница          | скилл `playwright-cli` (`resize`, `screenshot`, `eval`)             |

Браузер — `playwright-cli`, а не chrome-devtools MCP: у playwright-cli есть именованные
сессии (`-s=<имя>`), поэтому параллельные сабагенты не дерутся за одну вкладку.
У chrome-devtools выбранная страница общая на всех, параллельно с ним работать нельзя.

## Шаг 0. Вводные

Собери до начала работы, недостающее спроси одним вопросом:

- **Ссылка на фрейм** Figma с `node-id`. Ссылка на весь файл не подходит — попроси фрейм.
- **URL страницы**. Если стенд не поднят — предложи скилл `dev-stand`.
- **Брейкпоинты**. По умолчанию — ширины фреймов из макета (обычно у мобильного и
  десктопного фрейма разные `node-id`, тогда это два отдельных сравнения).
- **Состояние**: какие данные, залогинен ли, открыт ли дропдаун, hover/focus/error.
  Макет часто рисует состояние, до которого на странице надо дойти кликами.
- **Область**: вся страница или конкретный блок. Блок проверять проще и точнее.

## Шаг 1. Разбивка на задания

Одно задание = один фрейм макета × одна ширина вьюпорта.

- **1 задание** — делай сам в основной сессии (шаги 2–4).
- **2 и больше** — раздай параллельным сабагентам (`Agent`, тип `general-purpose`),
  все вызовы в одном сообщении. Промпт — шаблон из раздела «Промпт сабагента».
  Сабагент возвращает только таблицу расхождений, скриншоты остаются у него — ради
  этого и делим: картинки и дампы `get_design_context` съедают много контекста.

## Шаг 2. Снять макет

1. `get_screenshot` по `node-id` — эталонная картинка.
2. `get_design_context` по тому же `node-id` — размеры, отступы (auto layout padding/gap),
   типографика, цвета, радиусы, тени.
3. `get_variable_defs` — токены. Если цвет в макете привязан к переменной, сравниваем
   с токеном в коде, а не с hex: совпадение hex при другом токене — тоже расхождение.

Не утаскивай весь фрейм-страницу, если проверяем блок: бери `node-id` блока.

## Шаг 3. Снять страницу

```bash
playwright-cli -s=dr-<задание> open <url>
playwright-cli -s=dr-<задание> resize <ширина фрейма> 900
playwright-cli -s=dr-<задание> snapshot          # найти ref нужного блока
playwright-cli -s=dr-<задание> screenshot <ref> --filename=<scratchpad>/<задание>-page.png
```

Вычисленные стили ключевых элементов — одним `eval`, а не по одному:

```bash
playwright-cli -s=dr-<задание> --raw eval "el => [el, ...el.querySelectorAll('*')].slice(0, 80).map(n => {
  const s = getComputedStyle(n), r = n.getBoundingClientRect();
  return { tag: n.tagName, cls: n.className?.toString().slice(0, 60), text: n.innerText?.slice(0, 30),
    w: r.width, h: r.height, x: r.x, y: r.y,
    font: s.fontFamily.split(',')[0], size: s.fontSize, weight: s.fontWeight, lh: s.lineHeight, ls: s.letterSpacing,
    color: s.color, bg: s.backgroundColor, radius: s.borderRadius, border: s.border, shadow: s.boxShadow,
    pad: s.padding, gap: s.gap };
})" <ref>
```

Перед снятием дождись шрифтов (`document.fonts.ready`) и закрой куки-баннеры и попапы,
которых нет в макете. В конце — `playwright-cli -s=dr-<задание> close`.

## Шаг 4. Сравнить

Сначала глазами: открой оба скриншота (`Read`) и найди крупное — не тот порядок блоков,
пропавший элемент, другой перенос строк. Потом цифрами по чек-листу.

**Чек-лист и допуски:**

| Что                      | Допуск                                  |
| ------------------------ | --------------------------------------- |
| Размеры, отступы, gap    | ±1px (субпиксельное округление)         |
| font-size, weight, family| точно                                   |
| line-height              | ±1px                                    |
| Цвет                     | точно по токену; без токена — hex       |
| radius, border, shadow   | точно                                   |
| Иконки и картинки        | тот же ассет и размер                   |
| Тексты                   | совпадают, если в макете не «рыба»      |

**Не считать расхождением:**

- рендеринг шрифта и антиалиасинг;
- контент-заглушки макета против реальных данных (длина имени, число карточек);
- то, что макет не определяет: поведение между брейкпоинтами, если нарисованы только крайние.
  Это вынеси отдельным пунктом «вопросы к дизайну», а не багом.

**Severity:**

- `blocker` — сломан лейаут или пропал / лишний элемент, состояние не то;
- `major` — заметно глазу: не тот цвет или шрифт, отступ ≥ 8px, не та иконка;
- `minor` — 2–7px, line-height, letter-spacing, тень;
- `nit` — на грани допуска, косметика.

## Шаг 5. Отчёт

Для каждого расхождения найди место в коде: `grep` по классу, тексту или имени
компонента из снапшота. Если не нашёл — так и напиши, не угадывай.

```
## design-review: <страница> @ <ширина>px — <N> расхождений

| # | Sev | Элемент | Свойство | Макет | Вёрстка | Где в коде |
|---|-----|---------|----------|-------|---------|------------|
| 1 | major | Кнопка «Оформить» | background | --color-primary #1F6FEB | #2B7BF0 | Button.module.css:42 |

### Вопросы к дизайну
- …
```

Сводка по нескольким заданиям — сначала blocker и major со всех брейкпоинтов, потом
по брейкпоинтам остальное. Одинаковое расхождение на всех ширинах — одной строкой.

## Шаг 6. Правка и повторная сверка

Спроси, что чинить (по умолчанию — blocker и major). После правки повтори шаги 3–4
**только для упавших пунктов** и покажи, что закрылось, а что нет. Если правка — замена
хардкода на токен, это предпочтительнее подгонки hex.

## Промпт сабагента

```
Сверь вёрстку с макетом по скиллу design-review (шаги 2–4), одно задание.

Фрейм Figma: <url с node-id>
Страница: <url>
Вьюпорт: <ширина>x900
Состояние: <как довести страницу до нужного состояния>
Сессия playwright-cli: dr-<задание> (только она, другие не трогай)
Скриншоты клади в: <scratchpad>/

Код не правь. Верни только:
1. Таблицу расхождений в формате шага 5 (колонку «Где в коде» заполни через grep).
2. Список «вопросы к дизайну».
3. Пути к двум скриншотам (макет и страница).
```
