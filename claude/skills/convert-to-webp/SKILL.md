Конвертирует растровое изображение (PNG/JPG) в WebP с помощью shell-функции `convert-to-webp` (обёртка над `cwebp`, определена в дотфайлах пользователя), заменяет ассет в проекте и обновляет импорты в коде.

## Особенность окружения

Функция определена в `$DOTFILES/zsh/aliases.zsh`:

```zsh
function convert-to-webp() {
  for file in ./convert/*.png; do
    cwebp -m 6 -q 100 -mt -progress "$file" -o "${file%.png}.webp"
  done
}
```

Она **ожидает файлы в `./convert/*.png` относительно текущей директории** и кладёт результат туда же. Поддерживает только `.png` — `.jpg`/`.jpeg` не подхватятся без конвертации в PNG.

⚠️ В неинтерактивном шелле (Bash-тул) `~/.zshrc` не сорсится автоматически (zsh грузит rc-файлы только для интерактивных сессий), даже если `$DOTFILES` установлен в окружении. Перед вызовом всегда явно подгружай функцию:

```bash
source "$DOTFILES/zsh/aliases.zsh" 2>/dev/null
type convert-to-webp   # проверить, что функция подхватилась
```

Если не подхватилась (например, `$DOTFILES` не задан в этом окружении) — воспроизведи тело функции инлайн как fallback:

```bash
function convert-to-webp() {
  for file in ./convert/*.png; do
    cwebp -m 6 -q 100 -mt -progress "$file" -o "${file%.png}.webp"
  done
}
```

## Шаги

1. **Определи исходные файлы** — путь(и), которые дал пользователь, вложение Jira/Figma, или существующий ассет в репозитории (`find . -iname "*.png"` / `*.jpg`).

   Если исходник `.jpg`/`.jpeg` — сначала сконвертируй в PNG (на macOS): `sips -s format png in.jpg --out in.png`.

2. **Подготовь рабочую директорию** — используй scratchpad-директорию сессии, не репозиторий:

   ```bash
   WORKDIR=<scratchpad>/webp-convert
   mkdir -p "$WORKDIR/convert"
   cp <source1>.png <source2>.png "$WORKDIR/convert/"
   ```

3. **Запусти конвертацию** из `$WORKDIR` (функция работает от текущей директории):

   ```bash
   cd "$WORKDIR"
   source "$DOTFILES/zsh/aliases.zsh" 2>/dev/null
   convert-to-webp
   ls -la convert/*.webp
   ```

4. **Сравни размер файлов** до/после (`ls -la`). При `-q 100 -m 6` webp маленьких изображений с альфа-каналом иногда получается **больше** исходного PNG — если так, сообщи об этом пользователю прямо, не молчи. Решение (оставить webp ради единообразия формата / оставить PNG) — за пользователем.

5. **Перенеси результат в целевую директорию ассетов** проекта, сохранив соглашение об именовании, уже принятое рядом (обычно `src/**/assets/имя.webp`):

   ```bash
   cp "$WORKDIR/convert/имя.webp" src/.../assets/имя.webp
   ```

6. **Обнови импорты в коде** — найди все места, где импортируется старый файл, и переключи путь/расширение:

   ```bash
   grep -rln "assets/имя.png" --include="*.ts" --include="*.tsx" src
   ```

   Замени `.png`/`.jpg` на `.webp` в найденных импортах.

7. **Удали старый растровый файл**, только если он больше нигде не используется — перепроверь через `grep`, что не осталось других ссылок.

8. **Проверь визуально**, если есть возможность (запущен дев-сервер) — открой соответствующую страницу через Playwright/браузер, сделай скриншот, убедись что изображение не исказилось и не потеряло в качестве.

9. **Не коммить самостоятельно** — только по явному запросу пользователя (скилл `commit`).

## Чего избегать

- Не запускать конвертацию прямо в рабочей директории репозитория — мусорная `./convert/` может случайно попасть в `git status`. Только scratchpad.
- Не считать, что webp автоматически меньше PNG — при `-q 100` для маленьких изображений с альфа-каналом бывает наоборот; всегда проверять и сообщать.
- Не удалять старый PNG/JPG, не проверив все места использования через `grep`.
- Не забывать, что функция берёт только `*.png` из `./convert/` — `.jpg` не подхватится без предварительной конвертации в PNG.
- Не коммитить изменения без явного запроса пользователя.
