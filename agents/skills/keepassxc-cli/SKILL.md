Скилл для работы с базами KeePassXC из командной строки: пароли и SSH-ключи.
Проверен на `keepassxc-cli 2.7.12` (Homebrew) и macOS.

## Установка

Отдельной формулы `keepassxc-cli` в Homebrew нет. CLI приезжает вместе с приложением:
каска `keepassxc` объявляет его Binary-артефактом, поэтому brew кладёт в `PATH` симлинк
`/opt/homebrew/bin/keepassxc-cli` → `/Applications/KeePassXC.app/Contents/MacOS/keepassxc-cli`.
Каска уже перечислена в `install/Brewfile` дотфайлов.

Preflight перед первой командой скилла: если бинаря нет — поставь его и скажи об этом
пользователю, дальше не продолжай молча.

```bash
command -v keepassxc-cli >/dev/null || brew install --cask keepassxc
keepassxc-cli --version
```

Ставить всё, чего не хватает в сетапе целиком: `brew bundle --file=install/Brewfile`
из корня дотфайлов. `install/bootstrap.sh` пакеты не ставит — он занимается только
симлинками, brew запускается отдельно и вручную.

Man-страница (`man keepassxc-cli`) приезжает той же каской.

## Главное правило: секреты не попадают в переписку

Вывод любой Bash-команды целиком уходит в контекст сессии и в транскрипт. Поэтому:

- **Пароль записи отдавай через буфер обмена** (`keepassxc-cli clip`), а не через
  `show -s`. Флаги `-s` / `--all` печатают пароль открытым текстом — использовать
  только если пользователь явно попросил показать пароль в терминале.
- **Приватный SSH-ключ никогда не печатать** — только пайпом в `ssh-add -` или в
  файл с правами `600`. Не делать `cat` ключа, не показывать его «для проверки».
- Мастер-пароль базы не передавать аргументом командной строки, не класть в
  переменную окружения и не писать в файл.

## Мастер-пароль: диалог macOS

`keepassxc-cli` читает мастер-пароль со stdin. Bash-тул неинтерактивный, tty нет,
поэтому пароль спрашиваем у пользователя графическим диалогом `osascript` и сразу
пайпим в команду. Пароль не появляется ни в транскрипте, ни в истории шелла, ни в
списке процессов.

Определи хелпер в начале каждой команды (функция не переживает вызовы Bash-тула):

```bash
kp_pw() {
  osascript \
    -e 'display dialog "Мастер-пароль базы KeePassXC" default answer "" with hidden answer with title "keepassxc-cli" with icon caution' \
    -e 'text returned of result' 2>/dev/null
}
```

Использование — всегда пайпом, всегда с `-q` (иначе приглашение ввода уйдёт в вывод):

```bash
kp_pw | keepassxc-cli show -q "$DB" "путь/к/записи"
```

Если пользователь нажал «Cancel», `osascript` завершается с кодом 1 и отдаёт пустую
строку — `keepassxc-cli` ответит `Invalid credentials were provided`. Это отмена, а не
ошибка: не повторяй попытку молча, сообщи и остановись.

Каждая команда `keepassxc-cli` открывает базу заново, то есть диалог всплывает на
каждый вызов. Поэтому **объединяй работу в одну Bash-команду**, а не дёргай базу пять
раз подряд: сохрани пароль в локальную переменную одного скрипта и переиспользуй.

```bash
PW=$(kp_pw)
printf '%s\n' "$PW" | keepassxc-cli ls -q -R "$DB"
printf '%s\n' "$PW" | keepassxc-cli show -q "$DB" "запись"
```

Переменную объявляй только внутри одной Bash-команды и не экспортируй (`export` сделал
бы её видимой дочерним процессам).

## Где базы

Имена и пути баз — личные данные, в этом публичном репозитории их нет. Порядок поиска:

1. Переменная из `~/.env.d` (например `KEEPASS_DB`), если она задана.
2. `ls ~/*.kdbx` — базы лежат в домашней директории.

Если подходящих баз несколько — спроси пользователя, в какой работать, не угадывай.
Файлы `*.backup-*.kdbx` — это бэкапы, для записи их не выбирать.

## Пароли: типовые операции

```bash
DB=~/имя.kdbx

# структура базы (рекурсивно, плоским списком)
kp_pw | keepassxc-cli ls -q -R -f "$DB"

# поиск записи по подстроке (ищет по названию, логину, URL, заметкам)
kp_pw | keepassxc-cli search -q "$DB" "github"

# сводка по записи без пароля
kp_pw | keepassxc-cli show -q "$DB" "Сервисы/GitHub"

# только логин (пароль не печатается)
kp_pw | keepassxc-cli show -q -a UserName "$DB" "Сервисы/GitHub"

# пароль в буфер обмена на 15 секунд — основной способ отдать пароль
kp_pw | keepassxc-cli clip -q "$DB" "Сервисы/GitHub" 15

# TOTP в буфер
kp_pw | keepassxc-cli clip -q -t "$DB" "Сервисы/GitHub" 15

# новая запись со сгенерированным паролем
kp_pw | keepassxc-cli add -q "$DB" "Сервисы/Новый" -u "user@example.com" \
  --url "https://example.com" -g -L 24 -l -U -n -s

# правка полей существующей записи
kp_pw | keepassxc-cli edit -q "$DB" "Сервисы/Новый" --url "https://new.example.com"

# сгенерировать пароль, не трогая базу (пароль будет виден в выводе!)
keepassxc-cli generate -L 24 -l -U -n -s
```

Остальные команды: `mkdir`, `mv`, `rm`, `rmdir`, `db-info`, `analyze`, `merge`,
`export`, `estimate`, `diceware`. Полный список — `keepassxc-cli --help`,
флаги подкоманды — `keepassxc-cli <команда> --help`.

Записи адресуются путём от корня без ведущего слэша либо с ним: `Группа/Запись`.
Если в пути или названии есть пробелы и кириллица — оборачивай в кавычки.

## SSH-ключи

Соглашение о хранении, на которое опирается скилл: одна запись базы = один ключ.
Приватный и публичный ключ лежат **вложениями** записи (имена файлов сохраняются,
например `id_ed25519` и `id_ed25519.pub`), парольная фраза ключа — в поле `Password`
записи.

Атрибут `KeeAgent.settings` (интеграция ssh-agent в GUI KeePassXC) из CLI 2.7.12
проставить нельзя: у `add`/`edit` нет флага для произвольных атрибутов. Если он нужен —
это делается руками в GUI. Для работы через этот скилл он не требуется.

### Инвентаризация: что где лежит

```bash
PW=$(kp_pw)
echo "=== ключи в базе"
printf '%s\n' "$PW" | keepassxc-cli ls -q -R -f "$DB"
echo "=== вложения записи"
printf '%s\n' "$PW" | keepassxc-cli show -q --show-attachments "$DB" "SSH/rabochiy"

echo "=== ключи на диске"
ls -la ~/.ssh/*.pub
for k in ~/.ssh/*.pub; do ssh-keygen -lf "$k"; done

echo "=== загружено в агент"
ssh-add -l
```

Сверку делай по fingerprint (`ssh-keygen -lf`), а не по именам файлов: имя в базе и на
диске часто расходятся. Fingerprint публичного ключа — не секрет, его печатать можно.

Чтобы получить fingerprint ключа, лежащего только в базе, без записи на диск:

```bash
kp_pw | keepassxc-cli attachment-export -q --stdout "$DB" "SSH/rabochiy" id_ed25519.pub \
  | ssh-keygen -lf -
```

### Загрузить ключ в ssh-agent

Приватный ключ идёт из базы прямо в агент пайпом — на диск не попадает.

Ключ без парольной фразы:

```bash
kp_pw | keepassxc-cli attachment-export -q --stdout "$DB" "SSH/rabochiy" id_ed25519 \
  | ssh-add -t 3600 -
```

`-t 3600` — ключ сам выгрузится из агента через час. Без `-t` он останется в агенте до
перезагрузки; ставь TTL по умолчанию и убирай только по просьбе пользователя.

Ключ с парольной фразой: `ssh-add` спросит её на tty, которого нет. Фразу подаём через
`SSH_ASKPASS` — скрипт `scripts/ssh-askpass.sh` рядом со скиллом печатает значение
переменной `KP_PASSPHRASE`. Всё в одной команде, чтобы фраза жила ровно один процесс:

```bash
# директория скилла: ~/.claude/skills/keepassxc-cli (Claude Code)
# или ~/.agents/skills/keepassxc-cli (pi и прочие harness) — оба симлинка на дотфайлы
SKILL=$(ls -d ~/.agents/skills/keepassxc-cli ~/.claude/skills/keepassxc-cli 2>/dev/null | head -1)
PW=$(kp_pw)
KP_PASSPHRASE=$(printf '%s\n' "$PW" | keepassxc-cli show -q -s -a Password "$DB" "SSH/rabochiy") \
SSH_ASKPASS="$SKILL/scripts/ssh-askpass.sh" SSH_ASKPASS_REQUIRE=force \
  sh -c 'printf "%s\n" "$0" | keepassxc-cli attachment-export -q --stdout "$1" "$2" id_ed25519 | ssh-add -t 3600 -' \
  "$PW" "$DB" "SSH/rabochiy"
```

Здесь `-s` действительно печатает парольную фразу, но она уходит в подстановку
переменной, а не в вывод команды — в транскрипт не попадает. Не выноси это присваивание
в отдельный вызов Bash-тула и не делай `echo "$KP_PASSPHRASE"`.

Ограничение, о котором стоит сказать вслух: пока команда выполняется, парольная фраза
видна в окружении процесса. Для чужих пользователей она недоступна, но root её увидит.

Выгрузить ключ из агента: `ssh-add -d ~/.ssh/имя.pub`, снести все — `ssh-add -D`.

### Разовое использование без агента

Когда ключ нужен ровно на одну команду (`ssh`, `git`, `scp`) и в агент его класть не
хотят — временный файл в приватной директории с гарантированной уборкой:

```bash
TMPD=$(mktemp -d) && chmod 700 "$TMPD"
trap 'rm -rf "$TMPD"' EXIT INT TERM
( umask 077; kp_pw | keepassxc-cli attachment-export -q --stdout "$DB" "SSH/rabochiy" id_ed25519 > "$TMPD/key" )
ssh -i "$TMPD/key" -o IdentitiesOnly=yes user@host "uptime"
```

`IdentitiesOnly=yes` обязателен: иначе ssh сначала переберёт ключи из агента и может
упереться в лимит попыток аутентификации, так и не дойдя до нужного.

Подстановку процессов (`ssh -i <(...)`) использовать **нельзя** — проверено: OpenSSH
проверяет права файла и отвергает `/dev/fd/*` с `WARNING: UNPROTECTED PRIVATE KEY FILE`.

Временный файл клади в скратчпад-директорию сессии или в `mktemp -d`, но никогда в
репозиторий и никогда в `~/.ssh` «на минутку».

### Положить ключ в базу

Ключ уже есть на диске:

```bash
PW=$(kp_pw)
printf '%s\n' "$PW" | keepassxc-cli add -q "$DB" "SSH/novyy" -u "git" \
  --notes "ed25519, сервер example.com" -p        # -p спросит парольную фразу ключа
printf '%s\n' "$PW" | keepassxc-cli attachment-import -q "$DB" "SSH/novyy" id_ed25519     ~/.ssh/id_ed25519
printf '%s\n' "$PW" | keepassxc-cli attachment-import -q "$DB" "SSH/novyy" id_ed25519.pub ~/.ssh/id_ed25519.pub
printf '%s\n' "$PW" | keepassxc-cli show -q --show-attachments "$DB" "SSH/novyy"
```

Флаг `-p` (`--password-prompt`) читает парольную фразу со stdin, а туда уже идёт
мастер-пароль — в одном вызове это не совместить. Если у ключа есть фраза, заведи
запись без `-p`, а фразу положи отдельным вызовом, подав оба значения по очереди:

```bash
{ printf '%s\n' "$PW"; printf '%s\n' "$(kp_pw)"; } \
  | keepassxc-cli edit -q -p "$DB" "SSH/novyy"
```

(второй диалог озаглавь понятно — что просят именно парольную фразу ключа).

Новый ключ генерируем перед импортом обычным `ssh-keygen`:

```bash
ssh-keygen -t ed25519 -C "комментарий" -f ~/.ssh/имя
```

Проверь, что вложения в базе читаются (`attachment-export --stdout | ssh-keygen -lf -`
и сверка fingerprint с файлом на диске), **и только потом** предлагай удалить приватный
ключ с диска. Само удаление — по явному подтверждению пользователя, не самостоятельно.

## Подводные камни

- Без `-q` в вывод попадает приглашение `Введите пароль для разблокировки …` — при
  парсинге вывода это мусор, при `attachment-export --stdout` это порча содержимого.
- Локаль у CLI русская: сообщения об успехе и ошибках приходят по-русски, не завязывай
  разбор вывода на английские строки. Опирайся на код возврата.
- `attachment-export` в файл молча перезаписывает существующий файл — проверяй путь
  заранее.
- `keepassxc-cli open` даёт интерактивную сессию с одним вводом пароля, но в Bash-туле
  она бесполезна: между вызовами тула процесс не живёт.
- Одновременная правка базы из CLI, пока она открыта в GUI KeePassXC, ведёт к конфликту
  версий файла. Перед записью в базу спроси, не открыта ли она в приложении.
- Перед первой операцией записи (`add`, `edit`, `rm`, `merge`, `import`) сделай копию
  файла базы рядом: `cp "$DB" "${DB%.kdbx}.backup-$(date +%F).kdbx"`.
- `search` ищет подстроку без учёта регистра, но не поддерживает шаблоны — для обзора
  структуры используй `ls -R -f`.
- Мастер-пароль не кэшируй между вызовами Bash-тула: сохранять его во временный файл
  или переменную окружения сессии — недопустимо, даже если диалогов получается много.
